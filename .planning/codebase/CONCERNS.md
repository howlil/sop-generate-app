# Concerns

## Critical Issues

### 1. No Authentication on Server
- **Severity:** Critical
- All server endpoints are publicly accessible — no `AuthGuard`, no JWT middleware
- `@nestjs/jwt` and `passport` dependencies are installed but unused
- Any user can call `POST /api/v1/users`, `DELETE /api/v1/users/:id`, etc.
- **File:** `server/src/modules/users/controller/user.controller.ts` — no guards

### 2. Master PIN Hardcoded in Client
- **Severity:** Critical (security)
- `verifyPin()` always accepts PIN `'12345'` regardless of stored hash
- **File:** `client/src/lib/domain/tte.ts:22` — `if (pin === '12345') return true`
- Marks this as demo-only, but must be removed before any real deployment

### 3. TTE Signatures Stored in localStorage
- **Severity:** High
- Digital signatures (`TTESignaturePayload`) stored in browser localStorage
- Data lost on browser clear; no server persistence; not cryptographically secure
- **Files:** `client/src/lib/data/tte-storage.ts`, `client/src/hooks/useTTESignature.ts`

### 4. Client Has No Backend Integration
- **Severity:** High (by design for now, but must be resolved)
- All client data comes from seed JSON files and Zustand in-memory stores
- No API calls to server exist in the client
- `client/src/lib/api/` directory exists but integration is not wired up
- Most Zustand stores lose data on page refresh (no persistence)

## Tech Debt

### 5. Repository Interfaces Use `any` Types
- **Severity:** Medium
- `IUserRepository` and `IPostRepository` methods return `Promise<any>` / `Promise<any[]>`
- Defeats the purpose of TypeScript in the repository layer
- **Files:** `server/src/modules/users/repository/user.repository.interface.ts`, `server/src/modules/posts/repository/post.repository.interface.ts`

### 6. Posts Module is a Scaffold/Placeholder
- **Severity:** Medium (misleading)
- `PostsModule` models a generic "post" entity unrelated to the SOP domain
- Exists as a pattern reference only; will need to be replaced with domain modules (SOP, Peraturan, etc.)
- **Files:** `server/src/modules/posts/`

### 7. Typo Dependency
- **Severity:** Low but confusing
- `server/package.json` may contain `@nest/core` (missing `js`) alongside `@nestjs/core`
- Needs audit: `"@nest/core"` is not a real package — likely dead weight or install error

### 8. Dead `USE_MOCK` Flag
- **Severity:** Low
- Referenced somewhere in client but no longer active
- Confuses future developers about mock vs real data state

### 9. CORS Placeholder Domain
- **Severity:** Medium (deploy blocker)
- Production CORS origin falls back to `'https://domain-kamu.com'` if `ALLOWED_ORIGINS` is not set
- **File:** `server/src/main.ts:30`

## Fragile Areas

### 10. Non-Persisted Zustand Stores Lose Data on Refresh
- **Severity:** Medium
- `verifikasi-batch-store.ts` and `tim-penyusun-store.ts` have no `persist` middleware
- Any data added during session is lost on refresh
- Only `app-store.ts` (role) persists to localStorage

### 11. Auto-Generated Route Tree
- **File:** `client/src/routeTree.gen.ts`
- Never edit manually — regenerated by TanStack Router on every route file change
- If route files have errors, the generated tree may become stale/broken

### 12. BPMN/Flowchart Routing Algorithms Are Untested
- **Severity:** Medium
- Complex orthogonal routing and pagination logic in `client/src/components/sop/diagram/logic/`
- Zero unit tests; bugs here produce silent visual glitches in diagrams
- **Files:** `bpmnRouter.ts`, `orthogonalRouter.ts`, `flowchartPagination.ts`

### 13. Client-Side Role Auth is Trivially Bypassed
- **Severity:** High (when backend integration happens)
- `requireRoleBeforeLoad` checks Zustand store (localStorage) — client-side only
- Any user can set their role via browser devtools
- Must be backed by server-side session/JWT before production

## Performance Concerns

### 14. No Pagination on Client
- All SOP lists, evaluasi lists render from in-memory arrays without server-side pagination
- Will not scale once real data is loaded from API

### 15. Large Seed JSON Files
- `sop-detail.json` likely large (detailed SOP content)
- Loaded synchronously at app start; no lazy loading

## Missing Infrastructure

- No CI/CD pipeline configured
- No environment-specific config (`.env.example` not verified)
- No database migration scripts tracked (Prisma migrations folder not confirmed)
- No production build/deploy documentation
- No client-side error monitoring (Sentry, etc.)

    - server/prisma/schema.prisma — verify it has 18 models (output of Plan 01) before attempting migration
    - server/prisma.config.ts — confirm schema path is "prisma/schema.prisma" and datasource.url reads DATABASE_URL
    - server/.env — check DATABASE_URL and DATABASE_HOST/USER/PASSWORD/NAME are set (if missing, migration will fail)
    - server/src/common/prisma/prisma.service.ts — confirm import path `../../generated/prisma` matches output path in schema
  </read_first>
  <action>
    1. Verify `server/.env` contains the required environment variables. If DATABASE_URL or DATABASE_HOST/USER/PASSWORD/NAME are missing, the migration will fail with a connection error. The required variables are:
       ```
       DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/DBNAME
       DATABASE_HOST=HOST
       DATABASE_USER=USER
       DATABASE_PASSWORD=PASSWORD
       DATABASE_NAME=DBNAME
       ```
       If `.env` exists but DATABASE_URL is missing, add it in the format above using the same credentials as DATABASE_HOST/USER/PASSWORD/NAME.

    2. From the `server/` directory, run the migration:
       ```bash
       cd server && npx prisma migrate dev --name init
       ```
       This will:
       - Connect to MariaDB using DATABASE_URL from prisma.config.ts
       - Generate migration SQL in `server/prisma/migrations/YYYYMMDDHHMMSS_init/migration.sql`
       - Apply the migration to the database
       - Run `prisma generate` automatically

    3. If `prisma migrate dev` completes but `prisma generate` was not run automatically, run it explicitly:
       ```bash
       cd server && npx prisma generate
       ```

    4. Verify the generated client exists by confirming `server/src/generated/prisma/index.js` exists.

    **If migration fails with "Can't reach database server":** The DATABASE_URL is wrong or MariaDB is not running. Fix the .env and retry.

    **If migration fails with "Schema validation error":** Plan 01 had an issue — re-run `npx prisma validate` from Plan 01's verify step, fix schema, then retry migrate.

    **If migration fails with "previewFeatures" warning about driverAdapters:** Remove any `previewFeatures = ["driverAdapters"]` line from the generator block — Prisma 7 does not need it.
  </action>

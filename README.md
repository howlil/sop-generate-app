# SOPFlow

SOPFlow is a TypeScript web application with a TanStack Start frontend, a NestJS backend, Prisma, and MariaDB.

## Docker Compose

Create the deployment environment file:

```sh
cp .env.example .env
```

Only five values are required for the normal production stack:

```dotenv
PUBLIC_APP_ORIGIN=https://sopflow.example.com
DB_PASSWORD=replace-with-a-strong-database-password
JWT_SECRET=replace-with-a-random-secret-at-least-32-characters
JWT_REFRESH_SECRET=replace-with-a-different-random-secret-at-least-32-characters
TTE_ENCRYPTION_SECRET=replace-with-another-random-secret-at-least-32-characters
```

The three application secrets must use different values. Keep `TTE_ENCRYPTION_SECRET` stable across deployments and database restores because it protects encrypted personal P12 passphrases.

Validate and start the stack:

```sh
docker compose --env-file .env config
docker compose --env-file .env build
docker compose --env-file .env up -d
```

Stop it with:

```sh
docker compose --env-file .env down
```

### Internal defaults

The normal deployment does not require environment variables for database name/user, ports, JWT durations, Swagger, PDF storage paths, signing metadata, notification intervals, or WhatsApp tuning. Those values have application/Compose defaults.

The Compose stack uses:

- MariaDB database: `sop_biro_organisasi`
- MariaDB application user: `sop_app`
- MariaDB root password: generated by the official image during first initialization
- Backend internal port: `3001`
- Frontend internal port: `8080`
- Signed PDF storage: Docker volume `sop_pdf_data` mounted at `/app/storage/sop-pdf`

Do not set `PORT` or `APP_PORT` for the normal Compose deployment.

## Optional WhatsApp reminders

WhatsApp is disabled when these values are empty. Providing both credentials enables outbound WhatsApp reminders automatically:

```dotenv
WHAAPI_TOKEN=
WHAAPI_CHANNEL_ID=
```

A half-configured WhatsApp setup is rejected at backend startup instead of silently running with an invalid configuration.

## PDF signing and TTE credentials

Personal signing certificates are not configured through `.env`. Each supported signer sets up or uploads a personal PKCS#12 (`.p12`) credential through the application. The P12 data is stored per user in MariaDB, while its passphrase is stored encrypted and protected by the user's PIN plus `TTE_ENCRYPTION_SECRET`.

Signed PDF artifacts are stored separately in the persistent `sop_pdf_data` Docker volume. Legacy global `PDF_SIGNING_P12_BASE64` / `PDF_SIGNING_P12_PASSPHRASE` settings are not required by the normal personal-signing flow.

## Deployment on MyPaas

Use **Docker Compose** deployment mode and select `frontend` as the main service. The frontend listens on `0.0.0.0:8080` inside the container; MyPaas/Caddy handles public HTTP/HTTPS ingress.

Add the five required environment values from `.env.example` to the MyPaas project. Add the two WhatsApp credentials only if WhatsApp reminders are needed.
